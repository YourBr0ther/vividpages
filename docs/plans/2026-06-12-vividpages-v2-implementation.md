# VividPages v2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Design reference: `docs/plans/2026-06-12-vividpages-v2-design.md` — read it first.

**Goal:** EPUB → AI storyboard reader: upload *Assistant to the Villain*, run the full pipeline, read it with character-consistent scene art inline.

**Architecture:** pnpm monorepo. `apps/web` (Next.js 16 App Router: UI + API + SSE), `apps/worker` (one BullMQ consumer process for all queues), shared packages `@vividpages/db` (Drizzle + Postgres/pgvector), `@vividpages/core` (EPUB/segmentation/pipeline), `@vividpages/ai` (provider adapters). Backing: Postgres16+pgvector, Redis7, MinIO. AI on gaming PC: Ollama `http://10.0.2.192:11434`, ComfyUI `http://10.0.2.192:8188`.

**Tech Stack:** TypeScript, Next.js 16, React 19, Tailwind 4, Auth.js v5, Drizzle ORM, BullMQ 5, Zod, cheerio + fflate (EPUB), Vitest, Playwright.

**Conventions for every task:**
- TDD for all logic in `packages/*`: write failing test → run (expect FAIL) → implement minimal → run (expect PASS) → commit.
- Run tests from repo root: `pnpm -F <pkg> test -- <file>`.
- Commit after every green step: `feat:`/`test:`/`chore:` prefixes, end body with `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- The real book `Assistant to the Villain - Hannah Nicole Maehrer.epub` sits in repo root (gitignored). Cut small fixtures from it into `packages/core/test/fixtures/` (gitignored too — generated by script).
- All env config goes through `packages/core/src/env.ts` (zod-validated, one place).

## Milestone 2 — Ingest & Segment (core TDD territory)

### Task 8: Fixture script
**Files:** Create `scripts/make-fixtures.ts`, output to `packages/core/test/fixtures/`.
- Reads the real EPUB from repo root; copies it whole to fixtures as `book.epub`; also writes 2–3 extracted chapter XHTML files for fast parser tests. Run via `pnpm tsx scripts/make-fixtures.ts`. Fixtures gitignored; script committed. CI-less project: tests assume fixtures exist, script documented in README.

### Task 9: EPUB parser (TDD)
**Files:** Create `packages/core/src/epub/parse.ts`, `test/epub-parse.test.ts`. Deps: `fflate` (unzip), `cheerio`, `fast-xml-parser`.
- API: `parseEpub(buf: Buffer): Promise<ParsedEpub>` where `ParsedEpub = { metadata: {title, author, language, isbn?}, coverImage?: {data, mediaType}, chapters: Array<{idx, title?, html}> }`.
- Flow: unzip → `META-INF/container.xml` → OPF path → manifest+spine → resolve spine items to XHTML docs → chapter title from `<h1|h2>` or TOC (`toc.ncx`/nav doc) → keep raw XHTML per chapter.
- Tests (against real fixture): title === "Assistant to the Villain", author contains "Maehrer", chapters.length > 30, every chapter html non-empty, cover extracted.
- Steps: failing tests → implement container/OPF resolution → spine walk → titles → green → commit `feat(core): EPUB parser`.

### Task 10: Text extraction with paragraph offsets (TDD)
**Files:** Create `packages/core/src/epub/text.ts`, `test/epub-text.test.ts`.
- API: `extractChapterText(html): {text: string, paragraphs: Array<{start, end}>, sceneBreaks: number[]}`.
  - cheerio over `<p>`, `<h*>`, `<hr>`, `<div>` leaves; normalize whitespace; join paragraphs with `\n\n`.
  - `sceneBreaks`: char offsets where explicit break markers occur — `<hr>`, centered `***`/`* * *`/`⁂`/`~`-only paragraphs, or class hints (`scene-break`, `tb`). Marker paragraphs are dropped from text; the offset of the following paragraph is recorded.
- Tests: offsets round-trip (`text.slice(p.start, p.end)` is the paragraph), no `<` survives, break detection on synthetic + real chapter.
- Commit `feat(core): chapter text extraction with offsets`.

### Task 11: Scene segmentation (TDD)
**Files:** Create `packages/core/src/segment.ts`, `test/segment.test.ts`.
- API: `segmentChapter(input: {text, paragraphs, sceneBreaks}, opts?: {targetWords?: number}): Array<{startOffset, endOffset, wordCount}>`.
- Algorithm (deterministic, no LLM in v2 — revisit only if results are poor):
  1. Cut at explicit `sceneBreaks` first.
  2. Any segment > `maxWords` (default 1800) → greedily split at paragraph boundaries nearest multiples of `targetWords` (default 1200), preferring boundaries where the next paragraph opens with a time/location shift cue (`Later`, `The next morning`, `Meanwhile`, dialogue→narration transition) — simple regex heuristics, no AI.
  3. Merge any trailing fragment < 150 words into the previous scene.
- Tests: explicit breaks honored exactly; no scene exceeds maxWords (except single giant paragraph edge case — test it); offsets contiguous and cover whole chapter; real-book chapter produces 1–4 scenes.
- Commit `feat(core): scene segmentation`.

### Task 12: Ingest + segment pipeline stages
**Files:** Create `packages/core/src/pipeline/ingest.ts`, `pipeline/segment.ts`, `pipeline/progress.ts`; modify `apps/worker/src/index.ts`; create `apps/web/app/api/books/route.ts` (POST upload + GET list), `app/api/books/[id]/route.ts` (GET/DELETE).
- Upload route: multipart via `req.formData()`, 100MB cap, MIME+magic check (`PK` zip header), sha256, dup check, store to MinIO `epubs/{userId}/{sha256}.epub`, insert `books` (status `ingesting`) + `pipeline_runs`, enqueue `ingest`.
- `runIngest({bookId, runId})`: fetch from MinIO → `parseEpub` → store cover to MinIO → insert chapters (with extracted text + offsets JSON) → progress updates per chapter → enqueue `segment`.
- `runSegment`: per chapter `segmentChapter` → bulk insert scenes → status `analyzing`-ready (for M2, set status `ready` since no analyze stage yet — flip in M4) → progress.
- `progress.ts`: `reportProgress(runId, {stage, percent, currentStep})` → update `pipeline_runs` row. (SSE reads from Postgres — workers never hold web connections.)
- Verify end-to-end manually: compose up, worker running, `curl -F file=@book.epub` → poll book row → chapters+scenes in DB. Commit.

### Task 13: SSE progress endpoint
**Files:** Create `apps/web/app/api/books/[id]/events/route.ts`, `apps/web/lib/use-book-progress.ts`.
- Route: `ReadableStream` SSE, polls `pipeline_runs` + `books.status` every 1.5s, emits on change, closes on `ready|failed`. (Postgres LISTEN/NOTIFY is the upgrade path; polling is fine at this scale and survives worker/web being separate pods.)
- Hook: `useBookProgress(bookId)` → `{stage, percent, currentStep, status}` via `EventSource`.
- Verify with curl during an upload. Commit.

## Risks / watchpoints

- **Ollama model quality for structured extraction** — llama3.1:8b may be weak for character extraction. If repair-retries spike, try `qwen2.5:14b`+ on the 192 box before reaching for cloud.
- **ComfyUI workflow drift** — node-title-based patching mitigates; keep workflow JSON minimal.
- **Sequential analyze stage is the wall-clock bottleneck** (~150 scenes × LLM latency). Acceptable for v1; parallelize with roster snapshots only if painful.
- **EPUB variability** — parser is tested on one real book; keep parser failures non-fatal with clear error surfaced on the book card.
